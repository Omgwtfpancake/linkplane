# Linkplane v0.5.0 — first public alpha

Released 2026-09-13 as a GitHub pre-release. Alpha: the product has passed a clean-machine
test, and this is the first version other people can install. Expect rough edges and
please report them.

## What Linkplane is

Linkplane is an open, local-first control plane for real devices, starting with your
Android phone and your Linux desktop. One command, `linkplane`, and one small background
service give you the phone's status, file transfer, verified photo backup, notifications,
a live event stream your scripts can react to, and a local authenticated HTTP API.

## What this alpha proves

The whole first-user lifecycle has been run on a machine that had never seen Linkplane
(a fresh Ubuntu 24.04 VM with a real phone; `docs/testing/onboarding-run-002.md`): install
from public source with pipx, `linkplane setup` with a genuine USB-debugging authorization,
daemon installed and persistent across a reboot, first useful action 13 seconds after the
install command, safe rerun, clean uninstall, bounded purge, package removal.

## Highlights

- `linkplane setup`: one guided command from "installed" to "your phone is ready", safe to
  run again at any time.
- Device status, battery, ping, capabilities, and discovery over USB ADB.
- `send` files to the phone; `backup` photos incrementally with SHA-256 verification and a
  manifest; `notify` the phone; `find` it (ring, vibrate, torch).
- A background daemon that observes connection, battery, charging and Wi-Fi changes;
  `linkplane events` streams them; `linkplane watch` and `automations.json` rules react to
  them, with consent-gated script actions, job tracking, and an audit log.
- A local, loopback-only HTTP API (`/v1`) with per-client scoped tokens and Server-Sent
  Events, generated OpenAPI in `docs/openapi.json`.
- Screen mirroring, camera preview, audio and a virtual webcam through scrcpy presets.
- `linkplane uninstall` and `--purge` that never touch your backups or files.

## Supported platforms

| | |
|---|---|
| Supported | Arch Linux / Omarchy; Ubuntu 24.04 LTS |
| Expected to work | other current systemd-based distributions with Python ≥ 3.11 and `adb` |
| Not supported | no `systemd --user`, WSL, macOS, Windows |

## Android requirements

An Android phone, a USB data cable, Developer options, USB debugging, and one tap on
*Allow USB debugging?*. Nothing is installed on the phone. Termux and Termux:API are only
needed for the optional SSH provider and for clipboard/camera-capture.

## Installation

```sh
# Arch / Omarchy                       # Ubuntu 24.04
sudo pacman -S --needed python-pipx android-tools android-udev
                                       sudo apt update && sudo apt install pipx adb
pipx install https://github.com/Omgwtfpancake/linkplane/releases/download/v0.5.0/linkplane-0.5.0-py3-none-any.whl
pipx ensurepath        # once; then open a new terminal
linkplane --version
```

Alternative, same result: `pipx install "git+https://github.com/Omgwtfpancake/linkplane.git@v0.5.0"`
(needs `git`). See `docs/install.md`.

## First setup

```sh
linkplane setup
```

Then `linkplane status`, `linkplane notify "Hello from Linkplane"`, `linkplane send <file>`.
`linkplane doctor` explains anything that is off; `docs/troubleshooting.md` lists the
common cases with their error codes.

## Privacy and local-first behaviour

No account, no telemetry, no remote service. The daemon and its API listen on the loopback
interface only, and every API client needs a token you create. Actions you invoke move
data where you point them (a file you send, a backup you pull); Linkplane never uploads
anything on its own.

## Known limitations of this alpha

- Alpha: command output, the local API and file formats may change before 1.0; the
  `LP-` error codes and the `/v1` API only grow within a major.
- Clipboard read/write/sync and camera capture run through the Termux/SSH provider and need
  the Termux:API app on the phone; over plain USB ADB they are reported as unsupported.
- Screen, camera preview, audio and webcam need scrcpy (and v4l2loopback for the webcam);
  `linkplane screen --install` offers to install it.
- Wireless ADB and Termux/SSH are advanced, second-step providers; SSH-only devices are not
  observed by the daemon.
- With a USB-only profile and the phone unplugged, `linkplane status` appends the SSH
  provider's hints to the ADB ones; the message is correct but longer than it should be.
- No GUI, no MCP adapter, no native Android app, no remote or cloud access, no Windows or
  macOS.

## Uninstall

`linkplane uninstall` (service only), `linkplane uninstall --purge` (also Linkplane's own
directories; never your backups), then `pipx uninstall linkplane`.
