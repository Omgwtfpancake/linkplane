# Linkplane v0.6.0 — automatic camera-photo backup

Released 2026-09-17 as a GitHub pre-release. Alpha, still early: command output, the local
API and file formats may change before 1.0. Please report what breaks.

## What changed

Until now Linkplane did something only when you typed a command. v0.6 adds the first
workflow it performs on its own: **when your phone connects, Linkplane copies the new photos
and videos from its camera folder to your computer, verifies every copy, records the run, and
tells you only when something changed or went wrong.**

You turn it on once, with one question during setup or one command afterwards. Nothing is
enabled silently.

## Why this matters

Backing up phone photos by hand is the sort of chore people mean to do and then don't: plug
in, find the folder, copy, wonder which files are new, hope nothing was half-copied. Linkplane
already knew when your phone arrived; now it can act on that. Plug the phone in, walk away,
and the new photos are on your computer, checksum-verified, with one notification when
something was actually copied — and silence when there was nothing to do.

## How to turn it on

**New users.** `linkplane setup` asks once, after your phone is connected and every check has
passed:

```text
Linkplane can back up the photos and videos in this phone's camera folder automatically.
…
Turn on automatic camera-photo backup for this phone? [y/N]
Back up camera photos to [~/Pictures/Linkplane/phone]:
```

The default answer is no. Say `y`, accept the folder or type your own, and Linkplane takes it
from there — the first backup starts immediately.

**Existing users (v0.5.x).** Setup will not ask you again, on purpose: a rerun never nags.
Turn it on yourself, with the phone you already registered:

```sh
linkplane status                             # Backup ... off (turn on: linkplane automations enable photo-backup)
linkplane automations enable photo-backup    # default device, folder ~/Pictures/Linkplane/<device>
```

Both arguments are optional: `--device NAME` picks a phone when you have several, and
`--destination DIR` chooses the folder. Your existing configuration, profiles, history and
automations are kept; nothing is migrated or rewritten.

To look at it, change it, or switch it off:

```sh
linkplane automations presets                # what it is, whether it is on, where it writes, last run
linkplane automations list                   # the rule itself, as an ordinary rule
linkplane automations disable photo-backup   # off; the rule and every backed-up photo stay
```

## What exactly it backs up

- **The Android camera folder only** (`/sdcard/DCIM/Camera`). Screenshots, downloads,
  messaging apps' media and other folders are **not** included.
- **One folder per phone**, `~/Pictures/Linkplane/<device>` by default, so a second phone
  never lands in the first one's folder. A rule you already have keeps the folder it has.
- **One-way and additive.** Linkplane never changes or deletes anything on the phone, and
  deleting photos from the phone never deletes their backups. A file already in the backup
  folder that Linkplane did not create is never overwritten: if it matches the phone's copy
  it is recorded, otherwise it is left exactly as it is.
- **Verified.** Every file is downloaded to a temporary name, checked against the phone's own
  SHA-256, and only then put in place.

This is not photo sync, and not two-way sync. Deletions are never propagated in either
direction.

## When it runs, and what you hear

- **On connection**, including a phone already connected when the background service starts
  (after a login or a reboot).
- **New files copied** → one desktop notification: *"N new camera photo(s) or video(s) backed
  up to …"*.
- **Nothing new** → nothing at all. No notification, no noise.
- **A run failed** → one notification, *"Automatic camera-photo backup failed"*, with a short
  reason: not enough free space, the phone was not reachable, disconnected before it
  finished, cannot write to the folder, the folder cannot be used, a copy failed
  verification. The raw error is kept in `linkplane automations jobs` and the audit log, not
  put on your screen. No notification when Linkplane itself is stopping.

`linkplane status` shows the state and the last run:

```text
Backup      automatic camera-photo backup on, to /home/you/Pictures/Linkplane/phone
Last backup 2026-09-18 00:47, 1 new file(s) copied (134 B)
```

## Also in this release

- **Faster listing.** Linkplane lists the camera folder in one `adb` call instead of one per
  file. On a 652-file folder that is about 0.1 s instead of about 30 s, so a no-change
  automatic backup takes about 2 s instead of about 30 s. Phones whose toybox cannot do that
  fall back to the previous per-file listing automatically; a listing is always complete or
  an error, never partial.
- **Safer backups, for `linkplane backup` too.** Free space is checked before anything is
  downloaded (`LP-STORAGE-001`), files Linkplane did not create are never overwritten, and
  writing through a symbolic link inside the backup folder is refused.
- **A fixed event bug.** A phone plugged in after the background service started was reported
  as part of start-up, so `device.connected` rules without `on_initial` missed the first
  plug-in after a login. Only devices present when observation begins are "initial" now.
- **Rules can do more, if you write them.** A step may carry its own `if` condition over
  earlier results, and a rule may carry `on_error` steps that run once when a step fails.
  `linkplane automations list` and `GET /v1/rules` show both, and the preset a rule came from.

## The background service and your session

Linkplane's background service is a **`systemd --user` service**: it runs as you, with your
login session, and it is not a system-wide root daemon. On a normal desktop login it is
available for as long as you are logged in, and it starts again when you log in next. On a
machine where the user service manager stops after you log out (a headless server, for
example), automatic backup does not run while you are logged out. `loginctl enable-linger`
changes that if you want it; Linkplane never enables it for you. There is no tray icon and no
window in this release.

## Supported platforms and requirements

| | |
|---|---|
| Supported | Arch Linux / Omarchy; Ubuntu 24.04 LTS (clean-machine verified: `docs/testing/onboarding-run-003.md`) |
| Expected to work | other current systemd-based distributions with Python ≥ 3.11 and `adb` |
| Not supported | no `systemd --user`, WSL, macOS, Windows |

An Android phone, a USB data cable, Developer options, USB debugging, and one tap on *Allow
USB debugging?*. Nothing is installed on the phone.

**Automatic backup is USB-only in v0.6.** A backup folder is tied to the ADB identity it was
made with, so a phone backed up over USB and later connected over wireless ADB does not
continue the same backup yet.

## Installation

Choose your operating system and run only that section.

Arch Linux / Omarchy:

```sh
sudo pacman -S --needed python-pipx android-tools android-udev
pipx install https://github.com/Omgwtfpancake/linkplane/releases/download/v0.6.0/linkplane-0.6.0-py3-none-any.whl
linkplane --version
```

Ubuntu 24.04:

```sh
sudo apt update
sudo apt install pipx adb
pipx install https://github.com/Omgwtfpancake/linkplane/releases/download/v0.6.0/linkplane-0.6.0-py3-none-any.whl
linkplane --version
```

If `linkplane` is not found afterwards, run `pipx ensurepath` once and open a new terminal.

Upgrading from v0.5.x: `pipx install --force <the wheel URL above>`, then `linkplane setup`
(it restarts a service that still runs the old version). Your configuration is kept.

## Known limitations of this alpha

- Automatic backup covers the camera folder only, over USB only, in one direction.
- A failed run tells you what kind of problem it was, not which file; `linkplane automations
  jobs` has the detail.
- The fast listing path has been exercised on one phone model and toybox version so far; the
  per-file fallback is covered by tests.
- Everything in `docs/releases/v0.5.0.md` under "Known limitations" still applies: no GUI, no
  tray, no MCP adapter, no Android app, no scheduled triggers, no wireless reconnect, no
  Windows or macOS.

## Uninstall

`linkplane uninstall` removes the service and leaves your configuration; `--purge` also
removes Linkplane's own directories after asking. **Neither ever touches your backed-up
photos or any other file of yours** — the backup folder is yours, and Linkplane does not
delete it. Then `pipx uninstall linkplane` removes the program.
